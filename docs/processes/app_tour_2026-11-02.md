## 3. What Broke / Didn't Work

* **The session the app opens first** (`sess-new-canvas`, St. Mark's Church and four other Manhattan builds) — the viewport shows "4 models failed to load".
  - Console evidence: ```[External Loader] /models/st_mark_s_church_in_the_bowery_131_east__iso_tiles_52c85820.glb could not be reached (Unexpected token '<', "<!DOCTYPE "... is not valid JSON); retry 5 of 5```
  - Network evidence: the `/models/*.glb` requests answer 200 with the SPA's `index.html`; the files are in neither `public/models` nor `desktop-app/public/models` (the builds ran in another worktree; one of them hit ENOSPC there).
  - Suspected cause: the session references models that live in another worktree's `public/models`. Not investigated further.
* **Demo stage launch when a demo's button is found by an ancestor's text** — not an app bug; my first scripted click launched the first card. Recorded so the reproduction below uses the card-scoped click.
* **VFX NLE demo** — the program monitor shows a placeholder gradient; the demo's clips do not load. Console evidence: none seen. Not investigated.
* **"Botanical & Forest Procedural 3D Viewer" page** (`/forest_3d_viewer.html`) — draws grey spike trunks rather than trees after 15 s. Console: no page errors. Not investigated.
* **Sidebar** — every chat shows "now" as its age.
* **Side effects of the tour:** opening a chat re-saves its session file (mtime updated, e.g. `session-chat-1793213112459.json` to 2 Nov 07:12); three empty "New Chat" sessions were created; each opened chat ran the automatic visual check (`POST /gemini/verify-visual`, one Gemini Flash call).

## 4. Candidate Tool/Service Ideas

* **Open a saved scene file by URL** — a route or a "File → Open scene" that mounts a `scene3d.json` (e.g. the splat world's `public/tilesets/.../scene3d.json`) without a model call; this session used the stand-alone viewer page instead.
* **Missing-model check for saved chats** — the sidebar could mark a chat whose `/models/*.glb` files are not on disk, instead of the viewport retrying five times and showing HTML-as-JSON errors.
* **A quiet "view only" open** — reopening a saved chat for a demo should not re-save it or run the visual check.
* **Full-resolution screenshots from the Browser pane** — the pane captures 800 x 500 whatever the emulated size; this session needed a separate headless Chrome to get readable pictures.

## 5. Reproduction Steps

1. Add the `scratchbox-demo-tour` entry (ports 3760/3761/3762, `npm --prefix <main checkout> run dev`) and `preview_start` it.
2. Start `Google Chrome for Testing` (playwright's chromium-1234) headless with `--remote-debugging-port=9333`, connect with playwright `connect_over_cdp`, viewport 1600 x 1000.
3. Open the chats by their sidebar titles ("Build a 3D building of the Empire...", "Build the central building", "Write a Python proce...") and press **Open 3D**; for demos, open Settings → Admin & Demos and press the card's own **Launch Stage**.
4. For the splat world, run `scripts/walkable/build.sh` once, then open the viewer URL in section 2 in a tab brought to the front (a background tab never draws its first frame).
